## 아직 해결하지 않은 기능·시나리오 충돌
**현재 재현 및 소스 검증 표**: [최신 미해결 충돌 및 가상 시나리오](current-unresolved-and-synthetic-audit-20261030.md).

**C01·C02·C04 코드 수준 1차 충돌 해소:** C01의 투영 실패/0필드 writer 차단은 기존 구현+가상판정 확인, C02는 자동초안의 원본 D1/R2 SHA·검토 run을 같은 원장 `exportManifest`에 명시 인계하고 직원/변호사 재검수 화면까지 연결, C04는 직원화면·법률 AI·최종 출력·갈음 watcher 4개 경로가 같은 상담 run/페이지 문서종류/기준 감시 컨텍스트를 사용하도록 통일했다. **다만 실제 D1/R2, 전체 Node CI/빌드, Word 재생성/법원 서식 E2E는 미인증**으로 인수 보드에 유지한다. [교차 디버깅 및 격리 검증](c01-c02-c04-cross-agent-debug-20261030.md). **C03 관할별 전체 정책·상담 이력 스키마 분리는 사용자 지시로 P1 보류**한다. 기본 검토는 서울회생법원 기준이다.

## 진행 순서 및 통합 합격 기준
1. `0017`~`0021`을 순서대로 staging D1에 적용, 기존 데이터/트리거/권한/R2 pointer 영향 확인. 운영 적용은 별도 승인 및 배포 검증 후 진행.
2. `npm ci`, `npm run check:source`, `npm run lint`, `npm run build`, 최신 테스트 전체 실행. 검사 실패/미실행은 미인증으로 기록.
3. **C01/C02/C04 통합 인수 최우선:** 격리 합성 사건 3건 이상으로 상담 A→B 변경+갈음 복원, OCR 누락·0·오인식, 95 법률 체크의 0/불량 토큰 차단, 동일 D1/R2 artifact ID/실제 SHA, 직원 명시 인계→문안 편집→재생성→최종 검토본 직원/변호사 순차 승인, 2개 워커 경쟁/복구를 실제 실행.
4. 공식 법원 서식/실무준칙·시행일/관할 및 변호사 독립 검증. 합성 테스트 성능을 실사건 99% 정확도·인가확률로 표현하지 않음.

**불변 원칙**: 모든 값은 원문→검증 피처→사건값→계산 run/산식→법률 근거/검토→서식토큰·산출물 ID로 역추적되어야 하며, 미관찰/오인식/누락/해당없음/0/상충은 구분한다. 문서 생성 자체로 법원 제출 또는 인가가 이루어지지 않는다.
