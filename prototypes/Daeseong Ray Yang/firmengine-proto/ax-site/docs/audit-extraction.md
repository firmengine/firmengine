# OCR extraction safeguards

This document describes generic extraction safeguards. Case-specific observations, source page counts and sample execution details have been removed. It does not establish OCR accuracy.

## Findings and changes

| Severity | Failure mode | Change | Remaining limit |
|---|---|---|---|
| High | Credit inquiry history rows were treated as debt-like metadata. An opening/reported loan amount is not an outstanding principal; projection could create a typed current debt without a current claim basis. | Added `credit_report` source-only prompt/namespace. `reported_amount` is preserved as `credit_report.amount`; credit-report records never project as current debts. Generic debt projection now requires a quoted creditor and an explicit current-claim amount field. | This protects current typed projections; a reviewer must still classify historical credit facts against other evidence. |
| High | Health-insurance arrears columns were liable to map to loan principal/interest and generic debt classification; explicit zero and header-level unit needed separate preservation. | Added a health-insurance-arrears route and dedicated source fact keys for `premium_arrears`, `late_charge`, `total_arrears`, and `disposal_costs`, including aliases from legacy OCR keys. Records from this document type cannot project to typed debt or imply legal priority. | Source document classification must identify the arrears document; ambiguous cases remain for review. |
| High | A preconfigured document hint can disagree with the document visible on a page. This injected the wrong document-specific instructions before projection guards could identify the source type. | Extraction now treats manifest type and document guide as hints. The extractor must inspect the page itself and set the actual `PageRead.documentType`, with explicit distinction among credit inquiry history, current debt balance certificate, and health-insurance arrears statement. No additional classifier call per page was introduced. | A wrong model classification can still occur; page type and evidence remain auditable and require review where ambiguous. |
| High | The repair stage could re-read all fields, allowing a later verifier response to overwrite fields previously agreed. Missing checks and omitted table rows were not isolated from targeted repair. | First verification now creates explicit repair targets; only disagreements/missing checks go to repair. Existing agreements stay intact. Corrections require two corrected readings with matching value and explicit unit and citations. A genuinely missing first check may be resolved by a verifier agreement that matches the original reading. Missing-row rereads are separate, and only uniquely anchored first-pass agreements are merged; unmatchable pages remain incomplete. | Omitted-row recovery depends on row anchors. Unmatched rows intentionally remain partial for source review. |
| High | A model-generated `record.label` could be mistaken for a cited creditor, employer, or asset name. | Projection uses only cited field values. Debt projection requires a cited creditor and current claim basis; unsupported labels do not create typed objects. | UI/reviewer confirmation remains necessary where source names are masked or absent. |
| Medium | Income payer identity could be guessed from a name, and aggregation could be inferred prematurely. | `payer_identity_id` is projected only from a clear cited field. Income aggregation remains `unknown` and unreviewed. Prompt version is `luna-evidence-3.2.0`, so stale extraction cache entries do not silently reuse old instructions. | No provider call was run as part of this code audit. |
| Medium | Bank-account and lease facts can be mistaken for typed assets or current balances if the source record only documents account opening, a security ceiling, or claimed rent deductions. | Added explicit `bank_account.*` and `lease.*` source-field instructions, namespaced fact support, and unit-aware numeric fact preservation for deposit, secured balance, and arrears deduction. These keys do not create new typed entities. Account opening without a stated balance does not produce a zero balance; security setting amount is not a current secured balance; rent arrears are numeric only where the source states the amount and supporting basis. | These are source-only facts pending case-specific matching and review; no new asset/debt projection was added. |

## Retry and cache behavior reviewed

Pipeline repair is bounded by the existing attempt budget and persists the original read/review between stages. Targeted repair carries explicit `repairTargets`, and the resulting projection uses only the repaired read. Omitted-row retry saves a baseline read and verifier response, performs a fresh extraction stage, then preserves only fields whose first-pass verifier response actually agrees with the original value and unit. The matching logic requires a unique source anchor or a sole record of that category; otherwise it marks the page incomplete rather than silently dropping or overwriting the earlier fact. Cache identity includes the prompt version.

The audit does not establish end-to-end job readiness by itself. The server-level completion gate must continue to inspect evidence job states, including `review_required` and pending work; a manual inventory flag cannot represent successful extraction.

## Targeted regression checks

`tests/extraction.test.ts` covers no-unit blocking, source-only credit history amount preservation, health-insurance arrears zero/unit separation, metadata-only debt suppression, cited payer identity, and unit-aware bank-account/lease source facts without typed projection. `tests/pipeline-audit.test.ts` covers prompt-cache versioning, agreement integrity, targeted repair boundaries, omitted-row preservation, and second-read confirmation conditions. These are deterministic boundary tests; they are not a representative OCR accuracy benchmark.

## Not established

These safeguards do not establish OCR accuracy, missing-row recall over all pages, or a 99% field-level target. Remaining ambiguous values, unmatched table rows, unknown units, masked identities, and legal classifications require source review. A measured 99% claim needs a separately held-out, adjudicated field-level benchmark and must count omissions, unit errors, entity-link errors, and false typed projections as errors.
