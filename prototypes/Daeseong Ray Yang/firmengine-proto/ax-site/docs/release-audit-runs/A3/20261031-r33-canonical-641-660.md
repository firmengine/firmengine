## P2 격차 / 전문검토 조건 / 사용 금지
1. **P2 세금·공과금 material→typed 연결 공백:** #654 원 체납액과 #655 가산금은 `must_reconcile` 2개와 3서류×원천 라우트가 있지만 `tax_public_arrear` 직접 typed는 0. 등록 선언과 실제 검증된 `debt.principal`/`debt.interest` 사례행 사이의 연결을 별도 입증해야 한다. 원 체납액/가산금/독촉비용 #650/전체 납부액 #658을 모두 합산하면 **세부행+합계 이중계상 위험**. 가산금은 민사 이자와 같지 않고 공적 채권의 우선순위·채무자 해당 여부도 담당 변호사 검토 필요. 운영 사건 계산 실패를 재현한 것은 아니다.
2. **P2 차량 보강 피처 적용조건 미등록:** #659 `vehicle_registration::model_year`, #660 `vehicle_registration::plate_number`은 canonical+OCR supplemental 계약에 있지만 `vehicle_registry`의 `field-applicability-contracts.json` exact ID에는 **0/2**. 확장 필드의 별도 조건 정책 여부가 미확정이므로 누락된 요건의 검증 통과는 **0%**, 자동 보정·삭제·legal required 처리 금지. 차량번호·차대번호·등록소유자·지분·차종·평가기준일을 근거로 동일 차량 및 소유자 확인 후 계산에 연결할 것.
3. **P2 기간·단위 원본 판정 반례 후보:** `hasPeriod(role,family)`가 가족명에 `tax`가 있다는 이유로 시간역할 `not_applicable`인 #646 납세자, #649 권한기관, #651 납세의무자, #657 세목 등도 **기간 요구=true** 반환. **기댓 의미(기간 없음) vs 관찰(true)**의 모순은 원본 코드 분기 관찰 사실이며 실제 OCR 거절·계산 오류는 미실증. `hasUnit(type)`는 #659 `integer`에 unit check=true를 내지만 해당 원천 `canonical_unit=not_applicable`; 차량 연식을 금액·수량 단위 누락으로 해석하지 않도록 검토. 기존 [Draft PR #51](https://github.com/firmengine/firmengine/pull/51)의 기간 술어 관련 회귀(#451 과세연도)도 함께 통합검토 필요. 법률상 기간 필수 여부를 여기서 승인하지 않음.
4. **P2 소득증빙 과세기간·세금 구분:** #641–642 소득 기초기간은 typed 경로에 선언됐지만 #645 과세연도, #643 부과세액, #644 납부세액은 별도 source-only. 과거 신고액과 현재 소득, 납부세액과 비용, 신고기간과 지급기간, 공적 체납과 일반 채무원금을 무단으로 동일시하거나 원화 합산하지 않는다. 현재 CaseData·18계산·91입력의 값/산식 호출 또는 최종 문서 반영 여부는 미실행.
5. **갈음·법원보정·필요증거:** 이 문서 5종의 원문 기준 보정명령 필요항목/갈음 B+C 또는 해당 법원 제출 서식의 정확 토큰 연계 **미관찰**. source-only는 무용/삭제 대상이 아니며 검산·원문 재확인·추가서류 요청·법적 근거 검토 대상으로 남김. 원문 OCR 사실값/민감정보/키/.env/정답은 공개 repo에 기록하지 않음.
