## 법률 증거계약 P0 경계 — 실제 확인된 차이

현재 기본 `lib/risk-catalog.json`의 95 위험 중 `required_features`가 채워진 것은 **7개**, 비어 있는 것은 **88개**이다. 7개의 기존 키는 `income.monthly_net`, `tax_arrears.tax_type`, `assets[].gross_value` 등 **레거시 사건값 경로**이고, 등록된 693개 **정확한 canonical OCR ID와 일치하는 것은 0개**다. `lib/legal-evidence-criteria.ts`는 승인형 `requiredCanonicalFieldGroups`를 별도로 사용하고 **기본 seed `checks:[]`**로 시작하며, 미매핑은 `unmapped`/검토대기로 보류한다. **운영 DB 관리 기준정보에 별도 승인 계약이 존재하는지는 접근·실증하지 않았으므로 '운영 95개 전부 미승인'이라고 단정하지 않는다**. 법률 적합성·법원별 필요증빙 자동결론은 이 자료만으로 승인 불가.

첫 10개의 `account_garnishment` 원문 피처는 모두 `litigation_record` 문서 출처를 가지나 typed 법적 채무·실질 압류효력·변제액 계산으로 연결되는 명시적 변환은 없다. 리스크 `COND-20`(소송·지급명령·압류·경매), `DOC-02`(채권자목록)는 **법률 검토 후보**일 뿐 각 필드의 법적 요건/적용일/대상자/기간과 허용 증빙은 변호사 승인형 기준정보로 연결해야 한다. `garnishment_amount`, `seized_amount`, `released_amount`를 자동으로 채무원금이나 회수액에 더하지 않는다.
