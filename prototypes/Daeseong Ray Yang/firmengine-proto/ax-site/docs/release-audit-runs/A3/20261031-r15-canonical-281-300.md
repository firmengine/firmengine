## 재현된 P1 경계 후보 — 금액 출처는 있지만 사실 검증 상태는 미완료

`lib/material-calculation-source-gate.ts`의 **main 원본 함수**에서 금액이 원천/typed와 숫자로 일치하고 원문 ref가 유효하면 `fact.state="reported"` 또는 `"extracted"` 상태라도 `auditMaterialCalculatorSources().issueCount=0`인 경로를 확인. 원금잔액 #291 / 이자잔액 #285 각각 **reported×2 recognition 상태 및 extracted×2 recognition 상태**, 총 **8개 거짓 무경고**를 동일 원본 함수 본문(TypeScript 타입만 제거해 V8 격리 실행; `moneyValue`/원문 ref/currentFacts는 동일 입력 계약의 합성 stub)에서 재현했다. `verified/unreviewed`는 원천값 대조 가능하되 *법률 인정 상태는 미승인*이므로 별도 구분했다.

**독립 기대:** verified 사실만 이 `material amount source reconciliation`의 source validation을 통과. 원본 `reported/extracted`가 통과하는 것은 감사 오류 후보이며 실최종판정 거짓통과로 확정할 수 없다. 새 경고 `CALC_INPUT_SOURCE_INVALID`만 제안하고 금액·법률 인정·산식 의미 변경 없음. 별도 브랜치의 [Draft PR #63](https://github.com/firmengine/firmengine/pull/63)에 최소 한 조건 수정 + 합성 Node 회귀 테스트 4그룹을 **작성**했다. 격리 합성 비교 **26/26 기대 일치**, 수정 전 미검증 허용 8건 → 수정 후 0건. 프로젝트 Node import/test, 전체 CI, D1/R2/Cron, 법원 Word/PDF, 변호사 서명은 **실행하지 않았다**. 기존 동일 파일 [PR #44](https://github.com/firmengine/firmengine/pull/44)와 보존 병합 및 영향 재검토 전 Draft 유지.

`fact.recognition="unreviewed"`와 `state="verified"`인 경우 **source amount 검사만** 통과할 수 있으나 법률상 인정/채권액 확정/출력서식 승인과 동의어가 아님. source-only, 미관찰, null, 실제 0원, 비해당, 상충, 승인전 값은 각각 별개 상태; 원금·이자·연체이자·수수료·총액 임의 원화 합산 금지.
