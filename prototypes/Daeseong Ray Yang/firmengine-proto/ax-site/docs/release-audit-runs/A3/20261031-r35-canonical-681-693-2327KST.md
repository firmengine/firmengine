## 발견: 직접 소비처 공백 및 검사 술어 의미 P2 후보
1. **P2 #690/#692 기간검사 과잉:** 신청인 `taxpayer` 및 원천징수의무자 `withholding_agent`는 메타 `temporal_role=not_applicable`인데, 실제 `hasPeriod`는 family 이름에 `tax`가 들어간다는 이유로 **true/true**. 코드 반환과 해당 필드 의미의 불일치 후보다. 원본 페이지 추출 차단/법률 오판정은 미재현. 기존 [Draft PR #51](https://github.com/firmengine/firmengine/pull/51) 기간 술어 수정과 회귀 정책을 대조하되 기존 #451 과세연도 검증 후퇴 위험을 함께 검토할 것.
2. **P2 #688 과세연도 단위 과잉:** `tax_year`는 `integer`/단위 `not_applicable`/과세기간 `tax_period_year`인데 원본 `hasUnit`은 숫자 타입 정규식으로 **true**. 과세연도 유효성 검사가 원화/물량 단위검사와 혼동될 소지. 실제 OCR 거절이나 환산 오류는 확인하지 못함.
3. **P2 #684/#687/#689/#691/#693 과세/비과세 수당·세액 경계:** 직접 typed와 계산정책 미선언으로 모두 **증거전용(source-only) 상태**. 자동 `income.net` / D5103·D5110 토큰/법률 승격으로 처리하지 말 것. 원천징수 증빙의 해당 연도, 고용주·신청인 일치, 과세/비과세 수당 포함 관계, 공제·환급 금액과 status를 확인한 후 사람의 승인된 요건·산식에 맞게 새 매핑 여부 판단.
4. **P2 #681/#682 차량 시가 증거:** 평가방법/차량 식별자 자체는 금액이 아니며 앞선 #675 `must_reconcile→asset.grossValue` 공백과 독립적으로 **차량 동일성·소유자·지분·담보/평가시점 검산**에 보존한다. #675를 이번 13개에 포함해서 재합산하거나 보호된 자산으로 확정하지 않음.
5. **미관찰·null·명시적 0·비해당·상충·source-only·승인전의 상태 분리 필수:** 추출 스키마/행 방침이 있어도 사건별 원문 Fact·갈음·보정·공식 법원 서식·서류담당자/변호사 승인 검증 전에는 적합/합격 불가. 실제 원천/개인정보·비공개 정답/키/.env 공개 Git 반영 금지.
