## 3. 원본 증거→실제 소비처 분리

1. **실제 원천/SQL 계약**: `field-observation.ts`는 원본 page/document SHA, field/index, sourceState, verificationState 및 원문 인용/바운딩박스 등 관측 상태를 정의하고, `db/schema.ts`는 `extraction_records/extracted_features` 보존 경로를 정의한다. 실제 D1 OCR 행·페이지가 존재하는지 이 회차에서는 조회하지 않았다.
2. **법원 조건부 요청**: #162~171 전부 일반 `canonicalProjectionKey`의 직접 typed map과 `OCR_DECLARED_FORM_TARGETS`에 없음. `preapproval-correction-item-store.ts`는 실제 `correction_requested` event와 active PDF·페이지, 검증된 기한 Fact `court.correctionDeadline`/`corrections.deadline` 및 사람 입력 `requiredCanonicalFieldIds`를 조합하지만 **#168 `response_deadline`을 판정된 법원 기한으로 자동 승격하지 않는다**. 다른 명령의 기한/송달일/접수일을 자동 연결하거나 법원 수리로 확정하지 않는다.
3. **교육비 조건부 증거**: #172 청구액·#177 실제 지급액·#176 반복주기·#173~174 재학기간·#178 지급자/#180 수혜자를 구분. **월평균 추가생계비·법률상 인정 교육비의 직접 산식/서식 소비처는 미확인**. 0원/부재/미관찰/상충/제3자 지급은 다른 상태이며 자동 월환산·중복합산 금지. 직원·변호사 필요증빙/인정 범위 검토 대상으로 보존.
4. **법률 검토**: `risk-catalog.json` 95/`legal-catalog.json` 50/`legal-exceptions.json` 46에 이번 정확한 canonical ID 문자열 계약은 0. `legal-evidence-criteria.ts`의 관리 기준정보를 통한 전문가 승인형 가변 계약은 별도이며 **운영 D1 승인 데이터 미조회**. 문서분류 위험 후보는 정확 법률 증거계약 및 법원 적합성을 증명하지 않는다.

## 4. 발견 P1: 보정명령 인용문에 실제 페이지 근거가 없어도 검토 초안 허용

- 현행 main `lib/preapproval-correction-item-store.ts::validateCorrectionItemDraft`는 요청 문서/페이지 active 여부와 인용문 길이만 확인하고, 직원이 제출한 `orderQuote` 문자열이 **선택한 실제 법원 PDF 페이지 텍스트에 존재하는지 확인하지 않음**. 사용자가 같은 PDF의 다른 페이지 문구·허위 문구·텍스트 없는 페이지를 입력해도 해당 원본 근거로 보이는 항목을 만들 수 있음. **실제 고객 사건의 조작이나 법원 제출 오류 발생 사실을 발견한 것은 아니다.**
- GitHub 실제 원본·수정 함수본문에서 **타입전용 구문만 제거하고 동일 V8 격리 합성 테스트 수행**. 기대 시나리오 6개(정상 인용, OCR 공백 차이, 존재하지 않는 문구, 문구가 다른 페이지에만 존재, 빈 OCR, 페이지 내용이 다른 경우): **수정안 6/6**, 기존 함수에서는 **부정 4건을 거짓 허용**. 원본 domain 의존성은 합성 stub이므로 실제-import Node 및 전체 CI를 대체하지 않는다.
- [**Draft PR #48**](https://github.com/firmengine/firmengine/pull/48) — 정확 페이지 문자열과 인용문 공백정규화 동등성 확인; 원문이 없거나 다른 경우 `CORRECTION_ORDER_QUOTE_NOT_SOURCE_ANCHORED`로 fail-closed. 코드 파일+**Node 회귀 6개 작성**. PR은 **main 미병합**.
- **위험/보완 사항**: OCR 텍스트가 없는 스캔 PDF를 자동 차단할 수 있으므로, 원본 페이지에 연결된 **담당자 검증 전사 경로와 검토 UX**를 마련해야 실제 도입 가능. 열려 있는 [PR #19](https://github.com/firmengine/firmengine/pull/19)가 같은 `preapproval-correction-item-store.ts`를 수정하므로 병합 전 **동일파일 충돌 + 양쪽 회귀** 필수. 법원 명령의 법률적 충족·정당성·기한 인정은 담당 변호사 및 실제 법원 이벤트 검토가 필요.
