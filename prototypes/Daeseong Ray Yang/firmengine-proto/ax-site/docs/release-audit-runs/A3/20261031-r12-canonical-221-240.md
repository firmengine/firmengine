## 3. 코드 누락 후보와 안전한 수정 제안

`buildFeatureLineageAudit()`는 원천 family=`cash_deposit_asset`을 그대로 `reviewScope(family)`에 전달한다. 가상자산과 증권 확장 canonical ID는 그 일반 family 안에 있기 때문에 crypto/securities 추가 검토 후보가 빠질 수 있다. 단, 다른 `cash_deposit_asset::gross_value` 등 **공통 필드를 지갑·증권 전용 규정으로 오염시키지 않아야** 한다.

[Draft PR #56](https://github.com/firmengine/firmengine/pull/56)은 `reviewScope(family,canonicalFieldId)`의 정확 prefix만 보강하고, 법률 후보 `SEOUL-408`의 **공식 유효성/관할/시행일 자체는 검증하지 않는다**. 사람이 법률근거 및 GAP-13 적용조건을 확인해야 하며, `main`에는 병합하지 않는다. PR #22/#26/#30/#51/#54와 동일 파일 충돌 통합 후 전체 회귀가 필요하다. 제안은 데이터/계산/서식/법적 승인 로직을 변경하지 않는다.
