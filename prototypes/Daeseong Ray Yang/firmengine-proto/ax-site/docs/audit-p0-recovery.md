# 분류 복구·진술 연결·평가일 점검

## 작성 범위 관계와 가독성 개선

서로 다른 소제목 아래에 있는 진술 문단은 같은 제목을 반복하는 범위 필드만으로 연결하기 어렵다. `statement.scope_relation`은 작성선언, 끝맺음, 서명 및 원문의 모든 문단 인용을 명시한 제한된 JSON 관계다. 기존 추출 호출에서 제안하고, 별도 원문 검증 호출이 관계의 의미를 확인한 경우에만 사용한다. 현재 원본·페이지·문단·작성자 근거와 정확히 연결되지 않거나, 문단 누락·중복·순서 불명확·다른 작성자·철회·불량 범위 근거가 있으면 본문 연결을 보류한다. 같은 페이지나 같은 이름이라는 이유만으로 관계를 만들지 않으며 기존 수동 입력과 법적 인정 상태를 바꾸지 않는다.

관계 JSON은 원문에 인쇄된 문구가 아니라 직접 인용 사이의 연결을 표현하는 metadata다. 필드의 quote와 bbox는 작성선언의 원문 영역을 가리킨다. v2 관계는 명시적인 신청 의사 인용도 포함하며, 그 인용이 정확히 한 구성 문단에 포함되고 별도 의미 검증을 통과한 경우에만 서로 다른 parser record의 작성자·의사·서명 근거를 연결할 수 있다. v1과 기존 범위 방식은 기존 same-record 제한을 유지한다. 인쇄된 서명 안내나 빈 서명선은 실제 서명 근거가 아니며, 잘못된 근거를 자동 승인하지 않는다.

희미한 문서를 위한 보조 보기는 픽셀의 밝기에만 정해진 단조 변환을 적용한다. 생성형 복원·새 글자 생성·이진화는 하지 않는다. 원본과 중립 보기를 함께 유지하며, 새 계획은 보정 방식의 버전을 저장한다. 과거 계획은 기존 중립 변환을 계속 사용한다. 보정 보기 자체는 읽힘·정확성·증빙 역할의 근거가 아니며 분류의 원문 인용 조건과 최초 분류+추가 1회 한도를 유지한다.

`GET /api/cases/{id}/process?jobId={jobId}&view=classification`은 추출 전 역할 보류도 진단한다. 현재 사건·활성 문서·원본 해시·불변 저장 경로·페이지 이미지 해시를 확인하고 저장된 분류 관측과 실제 시도 기록만 반환한다. 기록이 없으면 없다고 표시하며 모델 호출이나 상태 변경은 하지 않는다. 완료된 증빙 판독의 조회·재투영 경로와 검증 기록은 별도로 유지한다.

이 변경은 모델 호출 수를 늘리지 않는다. 성능 개선 여부는 동일 입력의 회귀 평가와 사전에 동결한 새 사례 평가로 확인하며, 추출 문구가 부록에만 있는 경우와 공식 본문에 들어간 경우를 구분한다.

## 문서 분류 복구

역할이 미확정된 페이지는 최초 분류 결과가 증빙 또는 불명일 때 한 차례 추가 분류를 요청할 수 있다. 원본, 상단 확대, 전체 페이지 회전 보기를 비교한다. 두 후보가 모두 저장되기 전에는 추가 모델 호출을 사용하지 않는다. 시도 수는 호출 전에 저장하며 최대 두 번의 분류 호출 뒤에는 검토 요청으로 종료한다.

모델의 원시 역할이 증빙이고 신뢰도가 높아도, 가독성 또는 필수 원문 구조가 부족해 최종 관측 역할이 불명이라면 같은 제한 안에서 복구를 요청한다. 저장된 시도 수가 명시적으로 null·문자열·음수·소수 등 잘못된 값이면 추가 호출 없이 보류한다. 과거 기록에서 필드 자체가 없을 때의 호환 동작은 유지한다.

역할 복구에는 원문 표제 또는 발행주체와 문서 구조 인용이 함께 필요하다. 이 관측은 라우팅 근거이며 값·신원·법률 인정이나 원문 검증 기록이 아니다. 제출본·관리자료는 기존 원본 hash 기반 제외 규칙을 유지한다. 미확정 페이지에는 분류 복구 계획에 해당하는 후보만 허용하고, 일반 추출 복구를 허용하지 않는다. 후보는 원본·기준 이미지·계획 ID·위치·회전에 결합한다.

급여명세 유형의 국문·영문 별칭을 통합하고 지급총액·공제총액·실지급액·귀속기간을 별도로 추출하도록 안내한다. 파일명은 분류 근거가 아니다.

## 신청인 진술 연결

진술 문단의 record 번호만 달라졌다는 이유로 연결을 막는 문제를 수정한다. 연결은 원문에서 신청인인 작성자, 같은 작성자의 신청 의사와 서명, 같은 진술 구간이 명시적으로 연결될 때만 허용한다. 단일 문단도 같은 작성자 근거를 요구한다. 다른 작성자·불명확한 구간·상충·철회는 자동 결합을 막는다. 사용자 입력 진술은 보존하며 자동 진술은 최신 원장에서 파생한다.

여러 페이지의 진술은 명시적인 연속성 연결이 구현되기 전까지 자동 합치지 않는다. 원문이 불명확하면 서식의 완성도를 높이기 위해 작성자를 추정하지 않는다.

## 신청인 귀속과 생성본 검수

공식 진술서 본문뿐 아니라 신청서 요약과 부록의 신청인 진술 표도 같은 작성자 연결 함수를 사용한다. 명시적인 사용자 입력 또는 원문 작성자·신청 의사·서명·문단 범위가 확인된 진술만 신청인에게 귀속한다. 연결이 부족한 원문은 확인 필요 표시와 구분하여 중립적인 근거 표에 인용·출처·검증 상태와 함께 보존한다. 원문을 보존했다는 사실만으로 신청인 진술을 완성했다고 판단하지 않는다.

생성본 목록은 초안인지 최종 검토본인지 기록하고, 이 구분을 파일 ID·해시·사건 버전과 함께 검수 지문에 포함한다. 초안이나 구분이 없는 과거 목록에는 최종 검수 기록을 남길 수 없다. 최종 검토본 생성은 증빙 처리와 사건 검토 요건이 충족되면 가능하며, 아직 생성하지 않은 파일의 선행 검수를 요구하지 않는다. 생성 후 현재 파일 전체를 담당자, 변호사 순서로 확인한다. 재생성이나 보관으로 파일 집합이 바뀌면 기존 검수 기록을 다시 사용하지 않는다.

화면의 검수 완료 표시는 현재 최종 검토본의 사건 버전·필수 파일·검수 지문과 맞는 기록에서만 파생한다. 과거 기록이 저장되어 있어도 현재 파일의 승인처럼 표시하지 않으며, 변호사 완료 표시는 유효한 담당자 기록도 함께 필요하다. 과거 기록 자체를 삭제하는 마이그레이션은 수행하지 않는다.

## 재산 평가 기준일

재산 평가일이 없거나 실제 날짜가 아니면 해당 재산 기여액 계산을 보류한다. 유효한 날짜가 사건 산정기준일과 다르면 계산 가능한 금액은 검토용으로 유지하되 청산가치 비교를 확정하지 않고 최종 확정 경로를 차단한다. 전체 재산가치 검토 체크박스만으로 이 개별 날짜 불일치를 해소할 수 없다. 임의의 최근 N일 기준 또는 새로운 법률요건을 도입하지 않는다.

## 독립 감사에서 남은 문제

- 현재 검수 API는 로그인 계정과 생성본 지문을 기록하지만 담당자/변호사 역할의 전문 자격을 확인하지 않고 같은 계정의 두 단계 확인도 허용한다. 이를 독립된 두 사람의 검수로 해석하면 안 된다.
- 생성 파일 저장 뒤 사건 revision 비교가 실패하면 현재 manifest에 연결되지 않는 생성 파일이 남을 수 있다. 오래된 생성물을 현재 승인본으로 만들지는 않지만 정리 정책이 필요하다.
- 내부 감사 부속표와 제출용 파일의 구성 분리, 실제 공식 서식의 빈 항목, 여러 페이지 진술 연속성 및 전체 내용 평가 매핑은 별도 개선 대상이다.

## 검증 해석

코드 회귀검사, 모델 실호출, OCR 지정 필드 일치, 페이지 완료, 공식 서식 내용 일치, Office 물리적 보존은 각각 별도 지표다. 어떤 코드 검사 통과율도 다양한 실제 사건의 최종 문서 99% 정확도를 뜻하지 않는다. 정답·평가 입력·분모는 개발 결과에 맞추어 변경하지 않는다.

## 초기 분류의 원문 구조와 검증 좌표

초기 분류에도 표제·발행주체·문서 구조 관측을 요구한다. 제목의 일반적인 안내 문구만으로 관리 페이지라 판단하지 않으며, 구체 증빙 행과 별도 관리 구조가 동시에 관측되면 혼합 페이지로 보류한다. 저가독성은 불명으로 유지한다. 제출 서식의 제외 정책과 분류 시도 한도는 유지한다.

검증 요청은 원문 판독의 record 및 field에 서버가 부여한 좌표를 명시한다. 모델이 배열 위치를 새로 세어 다른 필드에 확인을 붙이지 않도록 하며, 범위를 벗어나거나 중복된 응답 좌표는 검증 근거로 사용하지 않는다. 문서의 값·단위·의미·인용을 확인하는 조건은 별도로 유지한다.

합성 평가 runner는 잘린 GET 응답을 제한적으로 재조회하고, 응답이 불명확한 POST/PUT 요청은 자동 재전송하지 않는다. 생성된 사건/문서 ID 및 이미 사용한 단계 수를 비공개 결과 경로에 기록하므로 전송 실패 후 같은 사건의 저장 상태부터 확인할 수 있다. 평가 정답이나 기대값은 runner에 입력되지 않는다.

중단된 평가를 이어갈 때에는 이전 요청 집합 전체, PDF 해시, 사건/문서 ID, 배포 SHA, 모델과 전체 호출 상한이 같아야 한다. `--resume-reads-dir`은 기존 원본 업로드나 사건 생성을 반복하지 않고 저장 상태와 복구 계획을 먼저 조회한다. 이미 끝난 사례와 보류 사례도 결과 집합에 유지하며 사용한 단계 수와 이전 실패 기록의 해시를 새 결과에 연결한다. 바쁜 작업이나 변경된 원본은 자동 재시작하지 않는다. PDF 렌더링부터 실제 보조 이미지 생성·업로드까지 실행하는 검사로 복구 경로를 확인한다.

## 저장 OCR의 선택적 원문 재검증

완료된 증빙 페이지의 저장 판독과 추출 provenance가 현재 원본/이미지에 결합되어 있고 판독 완전성이 확인될 때만, 원문 재검증을 별도로 요청할 수 있다. 서버 저장값만 사용하며 사용자에게 새 read payload를 받지 않는다. 과거 판독은 별도 archive로 보존하고 현재 verifier를 다시 호출하므로 새 OCR 결과나 기존 검토 승인으로 표시하지 않는다. 과거 검사·repair 횟수·commit proof는 새 검증으로 승계하지 않는다. 출처 metadata가 없는 구형 판독이나 불완전 판독은 재검증 경로에서 거부하며 새 원문 추출이 필요하다.

같은 PDF 안에 여러 종류의 문서가 포함돼도, 다른 종류 페이지의 원문 관측을 진술서 문단으로 다시 합산하지 않는다. 같은 진술서 페이지의 모호한 문단과 여러 작성자/페이지 경계는 계속 자동 연결을 막는다.
