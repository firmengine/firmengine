# FirmEngine AX — OCR 피처·법적계산 연결 디버깅 현황 (2026-10-30 KST)

이 문서는 **현재 GitHub main의 실제 반영 코드**와 새로 추가한 회귀 테스트를 분리해 기록한다. 운영 D1/R2 및 법원 전자소송 실화면 검증 결과가 아니다. 다른 작업의 LawGraph·상담·기준정보 수정은 유지한다.

## 필수 연결 규칙

모든 피처는 `문서 인스턴스 → 페이지 → 원문 행 → 필드 ID → 원본값/단위/기간/대상 → 검증·인정 → 소비처`를 잃지 않아야 한다. 소비처는 **(a) 증거/대조, (b) 계산 입력, (c) 사건별 법률 판단 근거, (d) 서식/검수, (e) 법원 요청·갈음서류 조건** 중 실제 목적에 따라 결정한다. 모든 693개 피처를 숫자 합계에 넣거나 소스 전용 피처를 쓸모없는 것으로 취급하지 않는다.

단수/복수는 원문에 근거한 **record/entity 단위**에서 정의한다. 같은 필드 ID가 여러 행에 존재한다는 이유로 `last wins`, 단순 배열 펼치기, 합계 중복 또는 한 채권/자산의 합산을 허용하지 않는다. `미관찰 / 누락 / 오인식 / 해당없음 / 0원 / 상충 / 미승인`은 별도 상태다. 인정·제출은 담당자와 변호사 게이트를 따른다.

## 완료가 아닌 부분 — 반드시 이어서 검증

1. 현재 고유 OCR canonical 693개 중 직접 typed 계산 변환은 최근 감사 기준 47개다. 그 밖의 646개는 **자동 계산 미연결 상태**이지 무용 또는 미저장이 아니다. 각 피처의 실제 법률/증빙/서식 소비처를 기능 단위로 승인·구현해야 한다.
2. 18개 법적 계산 모듈 91개 선언 입력에서 피처 ID·원문 단위·월/일/년 정규화, 결측과 0, 배열/행 범위, 원문 hash·법률 승인 및 출력 토큰을 **실제 저장 형태**로 모듈별 재실행해야 한다.
3. 사업소득: `business_sales_vat::income.sales.gross_sales`는 매출이지 순소득이 아니다. `business_costs_and_ledgers`의 개별 비용 행, `business_current_income_summary`의 입금·원천공제, `tax_income` 연간 과거 신고내역은 **같은 사업자·같은 발생 월·같은 거래/경비·같은 법적 기준**으로 검토하기 전 자동 더하거나 빼지 않는다. 매출·입금·세금·비용과 실제 계속 소득을 섞지 않는다. 12개월 기간 충족을 포함한 OCR→SQL→CaseData→서식 E2E는 미완료다.
4. 여러 채권/양도/담보 및 재산(은행 예금·보험·부동산·차량), 부양가족·생계비, 변제기간/청산가치/현재가치, 개별 채권자 배분의 **부정·경계·복수 행**을 추가 검증해야 한다.
5. 95건 법률 위험은 최근 `legal-evidence-criteria.ts`에서 승인용 정확 ID 계약을 편집 가능하게 만들었으나 기본 시드 `checks:[]`이다. **기준정보의 법률 검토·승인 없이 자동 충족으로 바꾸지 않는다**. 운영에 별도 승인 저장된 계약이 있는지는 DB 조회 전에는 알 수 없다.
6. 관할별 추가 서식·간이서식·청년회생·시행일/법원 재량 차이가 있다. 법원 홈페이지의 공개 서식과 실무준칙을 원본 근거로 사용하고, 민간 공개 코드나 법률사무소 블로그를 공적 확정값으로 주입하지 않는다.

## 다음 모듈 인수 순서

1. **사업소득/급여소득**: 같은 월 다수 매출·입금·비용 출처, 사업자 식별자, 중복, 개업/폐업, 원천징수, 소득 양수/음수·분모, 결손·제외사유. 12개월 검증·월별 서식 대조.
2. **채무/담보**: 원금·이자·비용·현재 잔액·동일 계약/양도/보증 중복/선순위 구분. 한도 및 법원 채권자목록 동일 숫자.
3. **재산/보험/가구**: 개별 계좌/보험/지분/현금의 중복·기준일·담보·면제액과 피부양자·생계비 입증/집계 구분.
4. **변제계획/서식**: 36·48·60개월 및 가변기간, 월별 회차 보존, 우선/재단·일반 배당, 현재가치 입력근거와 공식 서식 토큰 대조.
5. **통합 증명**: 실제 운영과 격리된 합성 사건 3개 이상에서 전체 흐름·재시도·동시사건·권한과 누락/오인식/해당없음을 확인한 뒤 서류별 담당자 검수.

**안전성 기준:** 값의 provenance가 없거나 복수 원천이 충돌하면 계산/법적 판단/최종 서식을 미확정으로 남긴다. 사람의 확인과 법원 인가를 AI·문서 생성이 대신하지 않는다.
