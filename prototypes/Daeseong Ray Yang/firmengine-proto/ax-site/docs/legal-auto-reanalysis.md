# 자동 법률 재판단 — 운영 계약

현재 코드 기준 2026-10-30. 실제 운영 배포, 스케줄러 등록 및 법원 전자서식 전체 적합성은 별도 검증이 필요합니다.

## 동작
1. SQL 변경 트리거가 사건 데이터 버전과 마지막 변경시각을 기록합니다. OCR·상담·원본 수정만 대상으로 하며 계산·법률 AI·자동초안 결과는 재판단 시간을 연장하지 않습니다.
2. 마지막 변경 이후 **10분** 조용한 기간이 지나면 정해진 계산 엔진만 실행합니다. 계산과 원본 스냅샷의 버전·해시·법령 기준 판본이 일치해야 진행합니다.
3. 예약 Worker는 최대 1건씩 확인하며 법률 검토 AI 95개 계약을 한 번에 6개씩 분석합니다. 모델 응답은 구조화된 근거·규칙·보완서류·후속조치를 포함하고 중간 진행률은 DB에 보존됩니다. 한 작업은 최대 한 배치만 모델을 호출합니다.
4. 95개 완료 시 사건용 LawGraph DB에 원본 버전·계산 실행 ID와 결합해 조건을 보존합니다. 계산·법률 검토·법령 판본이 하나라도 바뀌면 이전 결과를 최신 결과로 승인하지 않습니다.
5. 오류·충돌·필수자료 누락은 'attention_required'로 분석 내용을 기록합니다. 사람의 검토가 필요한 항목은 'legal_review'를 유지합니다. 조건을 만족하고 자료 처리가 끝난 경우에만 별도 검토용 초안을 생성합니다.
6. 검토용 파일은 기존 R2·artifacts DB에 저장하되 사건 원본 버전을 다시 쓰지 않습니다. 법원 제출·최종 확정·법률상 승인은 자동 수행하지 않습니다.
7. 실패한 작업은 지수 대기 후 최대 4회 재시도하며, 그 이상은 담당자 화면에 실패를 표시합니다. 인증한 담당자는 같은 데이터 버전의 실패 단계만 재시도할 수 있습니다.

## 상태
- `pending`: 분석할 계산 결과가 있으며 다음 배치 대기
- `running`: lease로 단일 실행 중
- `retry_wait`: 오류 후 다음 재시도 시간 대기
- `attention_required`: 오류·누락·상충 검토 필요
- `review_required`: 자동 초안 준비 조건 미충족 또는 별도 검토 필요
- `draft_pending`: 검토용 서류 준비 단계 대기
- `draft_ready`: 검토용 서류가 DB·R2에 생성됨
- `failed`: 자동 재시도 한도 도달
- `superseded`: 처리 중 사건 입력 또는 계산 판본 변경
- `skipped_fixture`: 보호된 합성·참조 사건은 예약 AI 호출 제외

## 진단/시험
- DB 마이그레이션: `drizzle/0017_legal_reanalysis_orchestration.sql` (이전 0000–0016 이후 적용)
- 사이트 상세: `GET /api/cases/:id/data?view=automation`
- 기존 처리 루트: `POST /api/case-data`; 완료된 소스·계산 판본만 AI 검토
- 담당자 실패 재시도: `POST /api/cases/:id/automation/retry` + `expectedDataVersion` (인증 필요)
- 실행 테스트: `npm run test:legal-auto`. 운영 배포 전 `npm run build` 및 실제 D1/R2/모델 실험과 Cron 등록 여부 별도 확인 필수.

**주의:** 95개 현재 체크는 전부 사람의 최종 법률 검토가 필요한 카탈로그입니다. AI가 법원의 인가 여부를 판정하거나 자동 승인할 수 없습니다. 표준 전자소송 양식의 필수 컨트롤은 별도 법원별 검증이 필요합니다.
