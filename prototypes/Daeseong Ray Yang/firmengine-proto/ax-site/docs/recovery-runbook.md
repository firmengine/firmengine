# 문제가 생겼을 때

| 상황 | 확인할 순서 |
| --- | --- |
| 저장 응답이 오지 않음 | 같은 요청을 다시 확인합니다. 새 요청으로 중복 저장하지 않습니다. |
| 다른 담당자가 먼저 수정함 | 최신 사건을 불러와 바뀐 값을 비교합니다. |
| 재계산이 대기·실패 상태임 | 담당자 작업에서 현재 사건에 해당하는 작업인지 확인하고 사유를 남겨 재시도합니다. |
| 자료 정정 뒤 검토가 풀림 | 새 값과 남은 근거를 대조한 뒤 필요한 검토를 다시 합니다. |
| 문서 편집이 충돌함 | 이전 문구, 직접 수정한 문구, 새로 생성된 문구를 비교합니다. |
| 이전 기준으로 복원해야 함 | 기준 담당자가 현재 기준과 복원 대상을 확인합니다. 이전 이력과 문서는 삭제하지 않습니다. |
| 기존 사건 형식이 맞지 않음 | 사건 업무 흐름에서 전환 내용을 먼저 확인합니다. 지원하지 않는 새 형식은 억지로 저장하지 않습니다. |
| 법원 점검이 일부 실패함 | 마지막 정상 자료를 보존하고 실패한 범위만 확인합니다. |

사건 판본과 처리 식별자를 함께 기록하면 문제를 찾기 쉽습니다. 오류 기록에 상담 원문, 주민번호, 비밀 키를 붙여 넣지 마세요.

자동 재시도는 5회로 제한합니다. 오래된 입력의 작업이나 실행 중인 작업을 중복 재개하지 않습니다. 이 재계산 경로는 OCR이나 유료 모델 분석을 다시 시작하지 않습니다.

보호 사건, 원본 평가 자료, 기존 승인·제출 파일은 임의로 바꾸거나 삭제하지 않습니다. 보관 파일을 정리해야 하면 다른 기록에서 사용하는지 먼저 확인합니다.
