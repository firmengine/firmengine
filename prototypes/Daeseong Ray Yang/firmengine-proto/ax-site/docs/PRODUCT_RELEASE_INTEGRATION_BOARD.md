## 4. 피처 693개 전수 소비처 확인 규칙

`node scripts/audit-product-contracts.mjs --fields`는 **693개 각각의 원문 선언 및 등록 ID를 열거**하고 계약이 고아·의미충돌인지 검사한다. 이는 downstream 사용을 증명하지 않는다. 각 피처마다 ① 증거 보존/대조 ② 계산 입력 ③ 법률·예외/누락 역질문 ④ 공식 서식/첨부 ⑤ 갈음/보정 ⑥ 원본 전용 ⑦ 법원/시행일별 비해당 이유를 검사하고 **각 상태의 테스트 영수증**을 연결한다. source-only 피처를 합산하거나 미사용을 곧 삭제하지 않는다. 인가 전 95 위험의 필수 출처 계약·법률인정은 사람 승인 전 빈 상태를 유지한다.

## 13. 시간별 실행 원장/자동화 핸드오프 규칙

- A1/A2/A3/A4는 각 시간별 고유 태스크에서 해당 체크 ID를 순서대로 처리한다. 한 회차당 가급적 2~5개 항목을 깊게 검증한다. 한 축 안에서도 담당자 역할이 편중되지 않도록 IT→DOC→CALC→LAW→DATA→AX를 순환한다.
- 모든 회차는 **현재 GitHub main HEAD → 수정 중인 다른 에이전트의 커밋/PR → 체크 ID → 코드/스키마/시험/공식 원문 → 합성 입력→기대값→실제 관찰 → 조치/commit·PR → 다음 체크 ID** 순서로 진행한다.
- 체크 완료 표시에는 최소 코드경로 + 실행 환경/명령 + 실제 시험 결과 + Git SHA를 기록한다. 운영 D1/R2/Cron, 실제 법원 양식, 변호사 승인은 별도 증명되지 않으면 미인증.
- 가능한 한 docs/release-audit-runs/A1/, A2/, A3/, A4/의 서로 다른 고유 시간별 파일에 결과를 보존하여 동시 감사가 하나의 긴 Markdown을 충돌 갱신하지 않게 한다. 중앙보드 갱신 시 **반드시 현재 파일 blob SHA 재조회 + 자기 ID만 변경**. 충돌이면 재조회 후 부분 병합 또는 분리 PR을 남긴다.
- 보고서에는 검토 ID/담당 관점/결함 심각도/재현 조건/개선된 파일 및 commit SHA/통과·실패·미실행/공식 법률 근거/다음 ID를 적는다. 자동수정은 하위 호환과 테스트를 증명한 최소 변경에 한하며 실제 배포·법원 제출/인가 확정은 하지 않는다.
