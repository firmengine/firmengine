# 로컬 기능 테스트 계획

이 문서는 수동 확인 절차와 기대 결과입니다. 실행·통과 결과를 기록한 보고서가 아닙니다. 정상·필수 누락·금액 충돌 프리셋과 허구의 파일만 사용합니다.

기준은 [양대성 기능 명세](../../../../../docs/specs/양대성-feature.md)의 후속 수정 §10과 AX v44의 [기능 목록](../../ax-site/docs/features.md), [업무 흐름](../../ax-site/docs/workflow.md), [상담·준비 서류](../../ax-site/docs/consultation-checklist.md), [변경사항](../../ax-site/docs/release-v44.md)입니다. 최초 명세의 임시 세션·60분 삭제 정책은 §10에서 사건 보존·복구로 대체됐습니다. 이 테스트 앱은 그중 브라우저 로컬 상태만 모의합니다.

## 주요 확인 절차

| ID | 시작 조건·조작 | 기대 결과 |
| --- | --- | --- |
| L01 역할별 동일 사건 | 정상 예제를 열고 의뢰인 → 담당자 → 변호사로 전환 | 같은 사건의 상담·자료·사실·작업·문서를 확인하며 역할 전환만으로 데이터가 초기화되지 않음 |
| L02 상담과 요청 자료 | 의뢰인 관점에서 상담 조건을 바꾸고 요청 목록 확인 | 조건에 맞는 준비 서류와 대상·기간·목적을 확인할 수 있음. 준비 서류는 법원 제출 생성물과 구별됨 |
| L03 자료 추가 | 가상 PDF 또는 이미지 파일을 요청 항목에 연결 | 이름·종류 등 메타데이터가 나타나고 지원되는 파일을 로컬에서 미리보기 가능. 자료 도착만으로 원문 사실이 자동 인정되지 않음 |
| L04 모의 추출 | 담당자 관점에서 데모 추출 동작 실행 | fixture의 예시 값과 문서·쪽·인용이 나타남. 선택 파일의 실제 내용을 OCR한 결과로 표시하지 않음 |
| L05 필수 누락 | 필수 누락 예제에서 계산·문서 상태 확인 | 누락을 0이나 충족 상태로 바꾸지 않고 필요한 보완·작업을 표시. 검토 완료를 허용하지 않음 |
| L06 금액 충돌 | 금액 충돌 예제의 후보와 근거 확인 | 서로 다른 금액과 확인 필요 상태가 보이며 자동으로 한 값을 정답으로 채택하지 않음 |
| L07 정정 사유 | 사실 값을 바꾸고 사유 없이 저장을 시도한 뒤 사유를 입력 | 사유 없는 정정을 막고, 저장하면 변경 이력·사실 상태·계산 결과가 함께 갱신됨 |
| L08 계산 일관성 | 같은 예시 금액으로 36·48·60개월을 번갈아 선택 | 동일 입력은 동일 결과를 내고 선택 기간에 따라 관련 총액이 바뀜. 기간 선택을 법적 허용 판단으로 표시하지 않음 |
| L09 작업 확인 | 누락·충돌 예제에서 남은 작업과 사실 화면을 오가며 보완 | 현재 미해결 항목과 다음 행동을 확인할 수 있고 해결 여부가 현재 사건 상태와 맞음 |
| L10 스냅샷 생성 | 정상 예제에서 문서 스냅샷 생성 후 원자료 수정 | 이전 스냅샷 내용은 그대로 남고 현재 입력의 변경이 조용히 이전 파일에 반영되지 않음 |
| L11 검토 순서 | 새 스냅샷에서 담당자 확인 전 변호사 검토 시도 | 담당자 → 변호사 순서를 지키며 역할·대상 스냅샷을 구분함. 새 문서는 미검토 상태로 시작 |
| L12 변경 후 재검토 | 담당자·변호사 검토를 마친 후 사실·상담·계산 입력 변경 | 과거 확인만으로 현재 사건을 검토 완료라 표시하지 않음. 새 스냅샷에 다시 검토가 필요함 |
| L13 출력 내용 | 현재와 과거 스냅샷의 JSON·HTML 보고서 다운로드 | 선택한 스냅샷의 값·검토 상태를 확인할 수 있음. DOCX·XLSX나 공식 전자소송 제출본으로 오인시키지 않음 |
| L14 로컬 보존 | 상담·사실을 변경하고 브라우저 새로고침 | 같은 브라우저에서 가상 사건 상태가 이어짐. 파일 미리보기는 재선택이 필요할 수 있음 |
| L15 초기화 | 변경한 상태에서 초기화 후 화면 확인 | 예제 상태로 돌아가 이전 테스트 입력·검토 상태를 현재 상태로 재사용하지 않음 |
| L16 사건 외부 호출 없음 | 개발자 도구 Network를 열고 상담·자료·계산·검토 조작 | 기존 AX API·외부 모델·법령 검색·파일 업로드 요청을 만들지 않음. 사이드바의 공개 날씨·시세·뉴스 조회는 별도이며 사건 내용을 보내지 않음 |
| L17 안전한 일괄 확인 | 정상·충돌 예제에서 원문 대조 확인란을 선택하고 정상 항목 일괄 확인 | 근거가 있는 정상 후보만 처리. 충돌·누락·직접 정정한 금액은 개별 확인으로 남음 |
| L18 실제 PDF 조작 | 합성 PDF를 열어 쪽 이동·확대·회전·형광 표시·메모 후 사본 다운로드 | 현재 PDF가 렌더링되고 페이지 연결 가능. 회전·표시는 내려받은 사본에 반영하며 원본을 바꾸지 않음. 메모는 JSON으로 구분 |
| L19 요구 항목 연결 | 같은 자료를 여러 요구에 연결하고 대상·기간·사유를 다르게 저장 | 자료 ID를 복제하지 않고 여러 연결 유지. 연결 해제·자료 철회 후 현재 충족 상태를 다시 계산 |

| L21 소득 행 검토 | 계산 → 재무 작업실에서 소득원을 추가하고 같은 출처·겹친 기간 입력 | 중복·기간 누락·미검토를 표시. 수정하면 행 확인이 해제되고 불완전한 합계의 핵심 금액 반영을 막음 |
| L22 채권·재산·예산 | 원금·이자·담보·분류와 재산 지분·처분액, 비용·우선배분을 변경 | 각 예시 합계와 일반채권 배분·부족·미배분을 구분. 저장은 이전 생성본을 무효화하며 핵심 금액 반영 후 원문 확인 필요 |

| L24 작업 CRUD | 업무함에서 추가·담당자 변경·기한·대기·완료·삭제, 같은 제목 재추가 | 공백 차이를 정규화한 같은 작업은 중복 생성하지 않음. 대기 사유가 필수이며 새 자료가 오면 완료·대기 작업을 다시 열음 |
| L25 기준 스키마 CRUD | 기준정보 관리자에서 6개 스키마를 전환해 새 행·수정·삭제·JSON 가져오기 | 필수 키·금액 형식·기간·자리표시자·중복 ID·관할 참조 검증. 참조받는 행 삭제와 읽기 전용 원본 변경·잠금 해제를 차단 |

| L28 절차 근거·순서 | 절차 기록에서 근거 자료·쪽·날짜·사유 없이 저장 시도 후 제출→접수→보정 순서 입력 | 근거와 유효한 날짜가 필수. 선행 사건 없는 접수·보정 제출과 날짜 역전을 차단. 모든 기록은 모의 이력이며 실제 제출은 비활성 |

| L31 문구·판본 비교 | 최신 초안의 문구를 사유와 함께 수정하고 이전 생성본과 비교 | 새 판본에 문구 수정이 남고 검토 확인을 다시 받음. 이전 문구와 파일은 보존. 금액은 원자료에서 수정하도록 안내 |
| L32 이동·접근성 | 데스크톱 사이드바·선택 사건 탭·모바일 메뉴·키보드 포커스·동작 줄이기 설정 확인 | 현재 메뉴가 표시되고 사건 전환이 유지됨. 모바일 메뉴를 닫을 수 있으며 reduced-motion에서 전환 효과를 줄임. 역할별 허용 메뉴만 노출 |
| L33 공개 정보 위젯 | 사이드바 정보 순환·일시정지·포커스·수동 새로고침·위치 버튼 허용/거절·네트워크 실패 확인 | 날씨·시세·뉴스의 출처·조회 시각·실패·캐시 상태를 구분. 위치는 명시적 허용 후에만 사용하고 사건 정보와 분리. 점심은 무작위 메뉴임을 표시 |

정상 흐름은 자료·후보값 확인 → 법률 검토 항목 해결 → 담당자 초안 생성 → 담당자·변호사 검토 순서입니다. 초기 법률 항목은 미확정이며 정상 예제도 L23을 거칩니다. 정상 흐름을 확인한 뒤 L05·L06에서 보완하고 L10~L13을 다시 진행하면 변경 영향과 문서 이력을 함께 점검할 수 있습니다. 테스트 중 발견한 차이는 프리셋, 역할, 조작 순서, 기대 결과와 실제 결과로 기록합니다. 전체 기능의 화면·소스 대응은 [기능 반영표](feature-coverage.md)를 참조합니다.

## v44에서 이어받은 상태 구분

- 자료를 받음, 필요한 기간이 충족됨, 원문값을 확인함, 법적으로 인정함은 다른 상태입니다.
- 소비자의 준비 서류, 법원에 작성할 문서, 생성한 문서의 검토 이력은 다른 목록입니다.
- 모의 추출·예시 산술·화면 검토는 실제 OCR 정확도나 법률 검토를 증명하지 않습니다.
- 문서 생성·다운로드·검토 완료로 제출·접수·보정·인가 상태를 자동 변경하지 않습니다.

## 별도 환경에서 확인할 항목

중복 요청·동시 수정·재시도, 기준 개정·승인·복원, 절차 근거는 위 표의 로컬 상태 전이로 확인합니다. 실제 API·사용자 인증·다중 사용자 동시성·저장소 장애 복구·법령 수집·예약 실행·실제 OCR·법적 계산·공식 DOCX/XLSX·전자소송 제출은 기존 AX 또는 별도 통합 환경의 검증 대상입니다. 기준정보 관리자의 부분집합 편집은 실제 AX 기준이나 이 앱의 예시 계산 산식을 바꾸지 않습니다. 이 프론트엔드의 정상 조작으로 외부 통합까지 통과했다고 기록하지 않습니다.

로컬 빌드·모델 검사는 앱 폴더에서 `npm run build`, `npm run test`로 실행합니다. 그 결과와 위 수동 확인 결과는 구분해서 기록합니다.
