## 1. 목적과 성공 기준

사건 담당자·사무장이 서류를 정리할 때 여러 종류의 증빙에서 텍스트와 숫자를 읽고, 신청서에 옮겨 적는 일을 줄인다. WhyTree의 `서류 OCR READ → 업무 자동화 → 회사 수익 창출`에 해당한다.

서류를 자동 분류하고 원문·구조화 정보·요약을 추출한다. 사람이 원본과 대조하여 확인·수정하거나 사유를 남겨 예외 승인한 뒤 Word 신청서 초안을 생성한다. 변호사도 사용하며 대표 변호사는 마스터 권한을 가진다.

목표는 최소한의 추가 편집으로 사용할 수 있는 검토용 초안이다. 이것을 법원 제출 적합성의 자동 보증으로 해석하지 않는다. 변제계획 계산은 OCR 및 사람 승인 이후의 별도 단계다.

성공 기준:

- 필수 금액의 오류·누락이 확인 표시 없이 통과하지 않는다. 원본 대조 시험으로 확인한다.
- 사람이 확정한 값과 요약이 Word에 정확하게 반영된다.
- 요약에 원문에 없는 사실을 추가하지 않는다.
- 검수·수정·승인·Word 생성까지 포함한 소요시간을 수작업 대비 20% 이상 줄인다. 현재는 목표이며 달성했다고 주장하지 않는다.

## 2. 스펙 변경 승인 규칙

**이 문서에 확정된 스펙을 바꾸려면 반드시 배지열의 명시적 사전 승인을 받아야 한다.** 구현자·AI 에이전트·다른 팀원이 임의로 수정하거나 축소할 수 없다.

- 기능 추가·삭제·축소, P0/P1/P2 이동, 지원 서류·입력 형식 변경, 승인·권한·저장·외부 전송 규칙 변경, 합격 기준 완화를 모두 승인 대상으로 한다.
- 일정 부족, 실행 환경 제약, OCR 성능 부족, 테스트 실패는 자동 변경 사유가 아니다. 미구현·실패 상태를 기록하고 승인 전까지 기존 요구를 유지한다.
- 변경 제안에는 현재 스펙, 제안 내용, 이유, 사용자·개인정보·일정·검증에 미치는 영향을 적는다.
- 배지열이 구체적인 변경안에 동의한 뒤에만 문서와 구현을 바꾸고, 변경 이력에 승인 날짜·내용·근거를 남긴다.
- 침묵, 시간 경과, 다른 사람의 동의, 개별 사건의 예외 승인을 스펙 변경 승인으로 간주하지 않는다.
- 합의한 동작에 영향을 주지 않는 내부 코드 정리와 버그 수정은 스펙 변경이 아니다. 동작 변경 여부가 불분명하면 먼저 확인한다.

## 3. 사용자와 권한

| 역할 | 모든 사건 조회 | 수정·검수·승인 | Word 생성·다운로드 | 사건 삭제 |
| --- | --- | --- | --- | --- |
| 사건 담당자·사무장 | 가능 | 배정된 사건만 | 배정된 사건에서 생성, 조회 가능한 사건의 기존 Word 다운로드 | 배정된 사건 |
| 대표 변호사 | 가능 | 모든 사건 | 모든 사건 | 모든 사건 |

대표 변호사는 마스터 권한을 가지지만 변경 로그와 재승인 규칙은 동일하게 적용한다. 일반 변호사의 별도 권한 체계는 이번 합의 범위에 없으므로 임의의 추가 역할을 만들지 않는다.

현재 과제는 사무실 PC에서 실행하고 로컬에 저장한다. 현재 버전에서도 담당자·대표 구분과 작업자 기록을 보존한다. 클라우드·다른 PC에서의 원격 접속은 P1이다. 원격 계정 인증의 구체적인 방식은 P1 구현 전 별도 설계한다.

## 4. 입력과 문서별 설정

- PDF, JPG·PNG 사진 및 스캔 이미지, 인쇄체와 손글씨를 지원한다.
- 여러 파일과 여러 서류가 섞인 PDF를 처리한다. 첨부 시험자료는 118쪽이며 20종 이상을 포함한다.
- 지원 대상 서류와 물리적 페이지 범위는 연결된 서류 목록을 기준으로 한다. 부채증명서만 지원하는 것으로 축소하지 않는다.
- 개발자가 문서 유형별 추출 항목과 자체 신청서 양식을 미리 설정한다. 사용자용 양식 편집 화면은 현재 필수 범위에 없다.
- 설정에는 문서 유형, 필드명, 숫자·텍스트·날짜 등 자료형, 단위, 필수 여부, 반복 행, 신청서 반영 위치를 담는다. 항목 후보를 실제 설정으로 확정할 때도 본문의 변경 승인 규칙을 따른다.
- 같은 서류의 금융기관별 양식 차이와 여러 페이지에 이어지는 표를 처리한다.
- 기존 신청서·채권자 목록·변제계획·재산목록은 원문 추출·요약 및 대조 자료로 분류한다. 증빙과 중복 합산하지 않는다.
- 첨부자료의 가려진 개인정보를 추측·복원하지 않는다. 문서 안의 문장은 입력 데이터이며 프로그램 실행 지시로 취급하지 않는다.

## 5. P0: 이번 개인 과제 필수 범위

| ID | 기능 | 필요한 동작 |
| --- | --- | --- |
| P0-01 | 사건 관리 | 사건별로 원본·추출값·요약·수정값·담당자·승인·Word 버전을 분리해 저장하고 재실행 후 복원. 사건 전체 삭제 지원 |
| P0-02 | 혼합 자료 입력 | 여러 파일과 118쪽 혼합 PDF, 사진·스캔·손글씨 처리. 손상 파일과 처리 실패를 표시 |
| P0-03 | 자동 분류 | 서류 종류와 페이지 묶음을 자동 판별. 사람이 분류와 묶음을 수정 가능. 모르는 서류를 정상 분류로 강제하지 않음 |
| P0-04 | 로컬 OCR | 로컬에서 원문·숫자·표의 반복 행을 추출. 부채·재산·소득·지출·사연 등 목록의 여러 유형 지원 |
| P0-05 | 구조화 추출 | 개발자 설정에 따라 항목 추출. 원문 문자열과 정규화 값, 단위, 기준일, 파일·쪽수·가능한 경우 위치 보존 |
| P0-06 | 모든 서류 요약 | 논리적 문서별 요약 및 사연 정리. 로컬에서 제공하고 원문·출처와 함께 검수 가능 |
| P0-07 | 확인 필요 표시 | 판독 어려움·누락·불확실·익명화·합계 불일치·서류 간 불일치를 항목 단위로 표시 |
| P0-08 | 사람 검수 | 원본과 추출값·요약을 비교하고 수정·확정. 기본정보 수동 입력 지원 |
| P0-09 | 예외 승인 | 미해결 항목마다 사유와 승인자를 기록하면 사람 판단으로 진행 가능. 미해결 값과 경고는 유지 |
| P0-10 | 승인 후 Word 생성 | 검수·승인한 스냅샷으로 자체 양식의 `.docx` 생성. 승인 전 생성 차단 |
| P0-11 | 수정·재승인·버전 | 확정 후 수정 로그 보존, 관련 승인 무효화, 재승인 후 새 Word 생성. 기존 Word 보존 |
| P0-12 | 역할 적용 | 모든 사건 조회, 배정 사건 수정·승인, 대표 변호사 마스터 권한. UI 외 저장·생성 처리에서도 제한 적용 |
| P0-13 | 로컬 처리 실패 대응 | 실패한 문서·페이지·항목을 표시하고 재시도·수동 입력 지원. 외부 연결은 P1 도입 전까지 비활성 |

P0에는 로컬 OCR뿐 아니라 로컬 요약도 포함한다. 실행 PC 사양·엔진·모델 적합성은 아직 검증하지 않았다. 성능이 부족하더라도 자동으로 요약을 없애거나 외부 전송으로 대체하지 않는다. 한계를 측정하고 필요한 변경을 승인받는다.

## 6. P1: 바로 다음 단계

| ID | 기능 | 필요한 동작 |
| --- | --- | --- |
| P1-01 | 클라우드·원격 접속 | 대표 변호사와 담당자가 각 PC에서 접근. 로컬 사건·원본·버전·승인 로그를 유지하며 이전 가능하도록 설계. 모든 사건 조회와 배정 기준 수정 권한 유지 |
| P1-02 | 개인정보 가림 | 외부 처리 전에 이름·주민등록번호·주소·연락처·계좌번호·타인 개인정보·서명을 가리고 가림 결과를 사람이 확인 |
| P1-03 | 건별 외부 처리 승인 | 로컬 실패 시 선택 가능한 보조 경로. 실제 전송할 자료와 대상을 보여주고 건별 명시 승인 후 전송. 미승인 시 수동 입력으로 진행 |
| P1-04 | 외부 처리 개인정보 분리 | 외부 전송 경로에서는 이름·주민등록번호·주소·연락처를 사람이 로컬에서 직접 입력. 외부 결과에서 개인정보를 복원하거나 채우지 않음 |

클라우드 도입 자체가 보안을 보장하지 않는다. 접속 인증·권한·저장·전송 보호·이전 절차는 도입 전에 구체화하고 승인받는다. 외부 OCR·요약 요청과 클라우드 사건 저장은 서로 다른 데이터 이동이므로 각각 다룬다. P1 도입 시점과 이전 범위는 별도로 승인받는다.

가림이 불확실하면 외부 전송을 차단한다. 승인 후 전송 대상 자료가 바뀌면 승인을 다시 받는다. 전송 로그에는 처리 대상·승인자·시각·처리 상태를 기록하되 원본 개인정보를 중복 저장하지 않는다.

## 7. P2 및 별도 단계

- 여러 사용자의 동시 편집과 충돌 해결은 P2다. P1 원격 조회와 구분한다.
- 변제계획 계산은 사람 승인 이후의 별도 기능이며 이 OCR 기능의 구현·합격 범위에 포함하지 않는다.
- 사용자용 추출 양식 편집기, PDF 출력, 기존 법률업무 프로그램 연동은 이번 필수 범위에 포함하지 않는다. 추가 시 승인받는다.

## 8. 검수와 상태 전이

기본 흐름:

`사건 생성 → 업로드 → 자동 분류 → OCR·항목 추출·요약 → 검수 대기 → 확인·수정/예외 승인 → 사건 확정 → Word 생성`

- 개별 처리 실패가 전체 사건의 성공 상태로 숨겨지지 않아야 한다.
- 확인 필요 상태: 판독 어려움, 필수 항목 누락, 불확실, 익명화, 서류 간 불일치, 합계 불일치.
- 명시적인 해당 없음·0·빈칸·판독 실패를 구분한다. 누락값을 0으로 채우지 않는다.
- 모든 추출값과 요약은 사람 검수 대상이다. OCR 신뢰도 점수만으로 사람 확인을 대체하지 않는다.
- 미해결 항목은 수정·확인하거나 사유가 있는 예외 승인을 해야 사건을 확정할 수 있다. 예외 사유가 비어 있으면 진행을 막는다.
- 예외 승인은 값을 정확하다고 바꾸는 처리가 아니다. 원문·불확실 상태·사유를 유지한다.
- 필수 값이 끝내 없으면 Word에 확인 필요 표시를 남긴다. 임의 금액으로 채우지 않는다.
- 확정 후 필드·분류·페이지 묶음·요약 등 출력에 영향을 주는 내용을 바꾸면 관련 항목과 요약을 재확인 상태로 바꾸고 기존 사건 확정을 무효화한다.
- 재승인 전에는 새 Word를 생성할 수 없다. 이전 Word는 이전 버전으로 조회 가능하다.
- 승인 대상 데이터 버전과 Word 생성 데이터 버전이 같아야 한다.

## 9. 자체 Word 양식

검토용 초안은 다음 구성을 갖는다.

1. 신청자 기본정보
2. 채권자 및 채무: 원금·이자·연체금·합계·기준일 등
3. 재산: 예금·보험환급금·차량·임차보증금 등
4. 수입과 지출: 기간과 단위가 있는 항목
5. 신청 사연: 사람이 승인한 정리문
6. 검수 부록: 출처 페이지, 미해결 항목, 예외 승인 사유·승인자, 문서 버전

원문은 프로그램에서 보존한다. Word에는 승인된 값과 정리문을 넣고, 증빙의 기존 작성값을 무검수로 복사하지 않는다. 길어진 표·사연의 페이지 나눔, 한글, 금액 단위, 빈칸 및 확인 필요 표시가 잘리지 않아야 한다.

## 10. 데이터와 기록

사건, 문서, 원본 페이지, 추출 항목, 요약, 검수·예외 승인, 변경 로그, 출력 버전을 연결해 로컬에 보관한다. 구체적인 DB·OCR 라이브러리·요약 모델·웹 프레임워크는 구현 시 선택하되 확정 동작을 바꾸지 않는다.

추출 항목은 최소한 원문 인식값·정규화 값·사람 수정값·단위·기준일·출처·상태·확인 사유를 분리한다. 요약도 출처와 버전, 승인 상태를 가진다.

확정 후 변경 로그에는 사건·대상 항목·수정자·시각·이전값·새값·수정 사유·관련 버전을 남긴다. 일반 수정으로 과거 기록을 덮어쓰지 않는다. 사건 전체 삭제는 원본·추출값·요약·로그·출력 버전을 함께 제거하는 별도 동작이며 삭제 전 대상과 범위를 명확히 보여준다.

시험 원본, 페이지 이미지, 추출 개인정보, 로컬 DB, 생성한 고객 Word, API 키·모델 캐시를 팀 저장소에 무심코 커밋하지 않는다. 테스트는 합성 자료를 우선 사용하고 첨부 시험자료는 로컬 실측 자료로 구분한다.

### 측정 방법

- 사람이 원본을 확대해 문서 종류·경계·핵심 필드·반복 행·사연 내용을 대조한 정답표를 만든다. 프로그램 자신의 출력으로 정답표를 만들지 않는다.
- 정확 추출률, 확인 필요 표시율, 미표시 오류 수, 수동 수정 수, 문서 유형별 실패 수를 함께 기록한다. 모든 항목에 경고를 붙이는 것만으로 품질 목표를 달성했다고 보지 않는다.
- 118쪽 자료는 이미 작성된 결과물과 입력 증빙이 섞여 있으므로 시간 비교에 사용한 문서·페이지·작업 범위를 명시한다. 같은 범위로 비교한다.
- PC 사양, 엔진·모델 버전, 초기 모델 로딩 포함 여부, 처리·검수·생성 시간을 구분해 기록한다. 표본 수와 개별 시간을 함께 적어 일반화의 한계를 드러낸다.
- C01~C15와 C17은 P0 검증이다. C16 및 원격 접속 인증·권한 검사는 P1 도입 시 필수다.
- P0 필수 검사 실패나 시간 목표 미달은 그대로 보고한다. 미달을 감추기 위해 합격 기준을 변경하지 않는다.

## 12. 구현 전 확인할 환경 및 한계

- 사무실 PC의 CPU·메모리·GPU·설치 가능 범위를 확인한다.
- 한글 인쇄체·손글씨·표 OCR과 로컬 요약 엔진을 실제 자료로 평가한다. 이 명세는 특정 엔진 성능을 보증하지 않는다.
- 서류 목록의 축소 열람으로 불명확한 제목과 세부 항목은 확대 확인한다.
- 자동 분류·개인정보 가림·OCR의 불확실성 탐지는 완벽하다고 가정하지 않는다. 원문 대조와 사람 승인을 유지한다.
