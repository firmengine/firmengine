## 1. 뿌리 (WhyTree)

- 씨앗 🌱: 서류 간 작성·논리 오류 Embedded AI Agent 대조/검토
- 새 방법 🆕: 한 화면 서류대조
- 실선으로 돕는 why: 같은 자료 반복 입력 줄이기, 신청서 작성 시간 단축, 전자 입력 실수 줄이기
- 점선으로 돕는 why: 보정명령 줄이기
- 고통: 직원과 변호사가 원본 서류와 화면 값을 손으로 하나씩 대조합니다.

## 2. 전제

- P0는 "원본 → 자동 작성 → 대조 검증 → 사람 처리 → 반영·이력"까지 완결합니다.
- 원본은 증명서입니다. 채권자목록, 변제계획 채권액, 개시신청서는 원본에서 나오는 출력값입니다. 이 출력값이 검증 대상입니다.
- 프로토에서는 실제 AI를 부르지 않습니다. 고정 JSON(mock)을 씁니다. 형식은 실제 AI와 같게 둡니다. P1에서는 함수만 바꿉니다.

## 3. 데이터 흐름

```
목업 원본 (JSON + HTML 표)
→ extract(원본) → 추출 JSON (값마다 원본 위치)
→ 채권자목록 → 변제계획 채권액 → 개시신청서
→ verify(원본, 출력 문서) → 지적 목록 (등급 + 원본 위치)
→ 사람 처리 (수정 승인 / 현행 유지)
→ 연관 문서 반영 + 합계 재계산 + 재검증
→ 이력 기록
```

## 4. 목업 원본 (1세트 고정)

실제 사건 서류는 쓰지 않습니다. 양식 3종, 채권 5건입니다. 5건 모두 원본과 연결합니다.

| 양식 | 건수 | 검증 목적 | 양식 특징 |
| --- | --- | --- | --- |
| 한빛카드 부채증명서 | 2 (1 = 카드대금, 2 = 카드론) | 한 원본에서 여러 행 추출 | 연회비 칸이 있음 (이 양식에만). 카드론 행은 연회비 0원으로 표시 |
| 새봄은행 부채증명서 | 2 | 날짜 필드 혼동 | 신규일자·만기일 칸이 나란히 있음 |
| 건강보험료 미납내역서 | 1 | 우선권 공과금 채권 | 보험료·연체금·미납액 계·최초 미납분 납부기한 칸이 있음 |

- 금융사명은 가상 이름입니다. 로고는 없습니다. "목업" 표시를 넣습니다.
- 원본은 이미지가 아닌 HTML 표로 그립니다. 칸마다 칸ID를 붙입니다. 양식 3종은 표 구조가 서로 달라서, 화면에서 차이가 보입니다.
- 모든 원본의 기준일은 하나입니다.
- 합계는 코드로 계산해 넣습니다.
- 이자는 원본에 적힌 값을 그대로 씁니다. 코드에서 이자를 계산하지 않습니다.
- 법비용 칸은 없습니다.

### 심은 오류 배치

| 채권 | 상태 | 등급 |
| --- | --- | --- |
| 한빛카드 1 (카드대금) | ② 이자에서 연회비 누락 | 확인 필요 |
| 한빛카드 2 (카드론) | 정상 | — |
| 새봄은행 1 | ① 발생일 칸에 만기일 기입 | 오류 |
| 새봄은행 2 | ③ 원금 자릿수 오타 (예: 8,000,000 → 800,000) | 오류 |
| 건강보험료 | 정상 | — |

## 5. 매핑 규칙

발생일:

| 양식 | 발생일 = |
| --- | --- |
| 은행 | 신규일자 (만기일 아님) |
| 카드사 | 이용일 (카드대금) / 대출일 (카드론) |
| 건강보험료 | 최초 미납분 납부기한 |

건강보험료 금액 (채권자목록 관행):

- 원금 = 미납액 계 (보험료 + 연체금). 원본의 "미납액 계" 칸에 연결합니다.
- 이자 = 0

기타:

- 연회비: 이자에 넣을지는 사람이 정합니다. (아래 6.2 연회비 규칙)
- 해당 양식에 칸이 없는 필드는 값 null, 원본 위치 null입니다. 출력에는 "—"로 보입니다. 예: 은행·건보의 연회비
- 법비용: P0에서 다루지 않습니다. 규칙은 P1에서 정합니다.
- 이 규칙들은 P1에서 실제 AI 추출 지침으로 다시 씁니다.

## 6. AI 경계

### 6.1 extract(원본) → 추출 JSON

값 하나마다 아래 형식입니다.

```
{ 채권ID, 필드, 값, 원본: { 양식ID, 칸ID } }
```

- 필드: 채권자명, 채권종류, 원금, 이자, 연회비, 기준일, 발생일, 우선권여부
- 칸이 없는 필드: `값: null`, `원본: null`
- 채권종류: 카드론, 카드대금, 신용대출, 건강보험료. 채권자목록의 채권 원인 칸에 씁니다.
- 금액은 원 단위 정수입니다. 쉼표는 없습니다.
- 날짜는 `"YYYY-MM-DD"` 문자열입니다.
- 비교는 정규화된 값으로만 합니다.
- 출력 문서의 칸 위치는 (채권ID, 필드) 고정 규칙으로 찾습니다. JSON에는 넣지 않습니다.
- 신뢰도 점수는 넣지 않습니다.

### 6.2 verify(원본, 출력 문서) → 지적 목록

- P0: 목업 원본 JSON(정답 값)과 비교합니다.
- P1: 작성 오류 대조만 AI로 바꿉니다. AI에게는 출력 값을 보여 주지 않습니다. AI는 원본만 다시 읽어 값을 돌려줍니다. 비교는 코드가 합니다. 출력 값을 보여 주면 AI가 그 값에 끌려가 같은 실수를 승인할 수 있기 때문입니다.
- P1의 verify = AI 원본 재추출(출력 값 비공개) + 코드 비교입니다. extract와는 다른 호출입니다.
- 문서 간 일치, 합계, 연회비 규칙은 P1에서도 코드로 검사합니다.
- verify는 값이 null인 필드를 비교하지 않습니다.

검사 종류:

| 검사 | 내용 | 등급 |
| --- | --- | --- |
| 작성 오류 | 원본 값 ≠ 출력 값 (금액, 날짜, 이름) | 오류 |
| 연회비 규칙 | 아래 참고 | 확인 필요 |
| 문서 간 일치 | 같은 값이 채권자목록 → 변제계획 → 개시신청서에서 같은지 | 오류 |
| 합계 재계산 | 원금·이자·총 채권액 합계 = 항목 합 | 오류 |

- 합계는 3종입니다: 일반 채권 합계, 우선권 채권 합계, 총합계(= 일반 + 우선권). 셋 모두 문서 간 일치를 검사합니다.

연회비 규칙:

- 이자 작성 오류 검사의 기대값은 {원본 이자, 원본 이자 + 연회비} 둘 다 허용합니다.
- 연회비 지적("확인 필요")은 원본에 연회비가 있고, 출력 이자 = 원본 이자일 때만 엽니다.
- 그래서 사람이 "원본 이자 + 연회비"로 승인해도 재검증에서 새 오류가 생기지 않습니다.

### 6.3 판단형 논리 오류는 P1

날짜 선후, 신청 직전 신규 대출, 재산 누락은 P0에서 하지 않습니다.

### 6.4 출력 문서의 금액

- 총 채권액 = 원금 + 이자
- 채권자목록에 "연회비(참고)" 칸을 둡니다. 칸 제목 옆에 "프로토 전용"을 표시합니다. 합계에는 더하지 않습니다. 원본 → 출력 연결을 보여 주는 용도입니다.
- 변제계획과 개시신청서에는 연회비 칸이 없습니다.

## 7. 한 화면 배치

```
┌──────────────────────────────────────────────────────────┐
│ 처리자: [사무직원 ▾]                         [초기화]    │
├──────────────────────────────────────────────────────────┤
│ 지적 목록   열린 지적 n건 / 처리됨 n건                    │
│ 등급 · 내용 · 원본 위치 · [수정 승인] [현행 유지 + 사유]  │
├────────────────────────────┬─────────────────────────────┤
│ 원본                       │ 출력                        │
│ [한빛카드][새봄은행][건보] │ [채권자목록][변제계획]      │
│                            │ [개시신청서][이력]          │
└────────────────────────────┴─────────────────────────────┘
                                   검사 테스트 4/4 통과
```

- 지적을 누르면 왼쪽은 해당 양식 탭으로, 오른쪽은 해당 문서 탭으로 바뀝니다. 그리고 두 칸이 함께 강조됩니다.
- 지적 ②를 누르면 원본의 이자 칸과 연회비 칸을 함께 강조합니다.
- 처리 버튼은 지적 목록의 각 행에 있습니다.
- 개시신청서는 채권액 관련 칸만 보여 줍니다.
- 수정 승인 후 바뀐 출력 값은 잠시 다른 색으로 보입니다.
- "검사 테스트 n/4 통과"는 화면 구석에 작게 보입니다.

## 8. 사람 처리

AI는 지적만 합니다. 값은 사람이 승인할 때만 바뀝니다. 승인 없는 자동 수정은 없습니다.

| 처리 | 동작 | 사유 |
| --- | --- | --- |
| 수정 승인 | 출력 값을 바꿉니다. 기본값은 원본 값입니다. 지적 ②의 기본값은 원본 이자 + 연회비입니다. | 원본과 다른 값으로 바꿀 때 필수 |
| 현행 유지 | 값을 바꾸지 않습니다. | 필수 |

- 수정 승인하면 그 값을 쓰는 모든 문서(채권자목록 → 변제계획 채권액 → 개시신청서)에 반영합니다. 합계를 다시 계산하고, verify를 다시 돌립니다.
- 처리할 때의 값을 지적에 저장합니다. 재검증 때 현재 값이 저장된 값과 같으면 "처리됨"을 유지합니다. 다르면 지적을 새로 엽니다.
- "처리됨" 지적은 흐리게 보이고, 처리 구분(수정 승인/현행 유지)을 함께 보여 줍니다. 열린 지적 수에는 세지 않습니다.
- 처리자는 화면 위에서 고릅니다: 사무직원 / 변호사. P0에서는 권한이 같습니다.

## 9. 이력

- 항목: 시각, 처리자, 문서·필드, 변경 전 값, 변경 후 값, 원본 위치, 처리 구분, 사유
- 추가 함수 하나만 둡니다. 수정·삭제 함수는 없습니다.
- 추가된 항목은 freeze합니다. 코드에서도 바꿀 수 없습니다.
- 출력 영역의 "이력" 탭에서 봅니다. 필드로 걸러 볼 수 있습니다. 별도 화면은 없습니다.

## 10. 형태와 저장

- HTML 파일 하나입니다. 외부 라이브러리와 CDN은 쓰지 않습니다. 시연장 네트워크가 없어도 열립니다.
- 상태와 이력은 메모리에만 둡니다. 새로고침하면 처음 목업 상태로 돌아갑니다.
- "초기화" 버튼으로 처음 목업 상태로 돌아갑니다.

## 11. 검사 테스트 (페이지 안에서 실행)

1. 개시신청서 총합계에 예전 값 → 문서 간 불일치 지적
2. 채권자목록 합계 ≠ 항목 합 → 합계 오류 지적
3. 우선권 채권이 일반 합계에 섞임 → 우선권 합계 불일치 지적
4. 정상 문서 → 지적 0건
5. 문서 간·합계 지적 → 수정 승인만 허용 (현행 유지 불가). 작성 오류 지적은 둘 다 허용

심은 오류 3개는 모두 추출 값 오류입니다. 그래서 화면 시연에서는 문서 간 불일치와 합계 오류가 나오지 않습니다. 이 두 검사는 위 테스트로 증명합니다.

## 12. P0 완료 기준

- [ ] 채권 5건의 각 필드가, 해당 양식에 칸이 있는 경우 원본에서 출력값까지 연결됨
- [ ] 심은 오류 3개를 모두 지적하고, 정상 2건은 지적하지 않음
- [ ] 채권자목록 = 변제계획 = 개시신청서의 일반·우선권·총합계 3종이 각각 일치
- [ ] 모든 지적에서 원본 칸과 출력 칸이 함께 강조됨
- [ ] 수정 승인 시 연관 문서 3종에 반영되고, 재검증에서 해당 지적이 "처리됨"으로 바뀌며 열린 지적 수에서 빠짐 (새 지적이 생기지 않음)
- [ ] 현행 유지 시 값은 그대로이고 사유가 기록되며 "처리됨"으로 표시됨
- [ ] 모든 처리 건이 변경 전/후 값과 함께 이력에 남음
- [ ] 검사 테스트 5/5 통과

## 13. 범위 밖 (P1)

- 파일 업로드
- 실제 AI 추출과 AI 재추출 verify
- 판단형 논리 오류 (날짜 선후, 신청 직전 신규 대출, 재산 누락)
- 소득·재산 증빙 기반 변제액·청산가치 계산
- 승인 없는 자동 수정
- 사무직원 / 변호사 권한 차이
- 신뢰도 점수
- 법비용 규칙

## 14. 빌드 중 결정

스펙에 없던 부분을 만들면서 정했습니다. 작성자가 확인했습니다.

1. **건강보험 기관명**: "누리건강보험공단 (가상)"입니다. 금융사처럼 "가상 이름" 원칙을 적용했습니다.
2. **AI 추출 위치 표시**: AI가 원본의 다른 칸을 읽었으면, 지적에 그 칸을 함께 보여 줍니다. 예: 지적 ①에 "AI 추출 위치: 새봄은행 부채증명서 · 1행 만기일".
3. **이력의 "반영 문서" 열**: 처리 한 번으로 값이 바뀐 문서를 적습니다. 예: "채권자목록, 변제계획, 개시신청서".
4. **테스트의 정상 문서**: 모든 값이 맞는 상태 = 연회비를 이자에 포함한 상태입니다. 연회비 규칙은 "출력 이자 = 원본 이자"일 때 지적을 엽니다. 그래서 연회비를 포함하지 않으면 정상 문서에서도 지적이 나옵니다.
5. **날짜 표기**: 원본 양식에는 `2022.06.20`, 출력 문서에는 `2022-06-20`으로 보입니다. 비교는 정규화된 값으로만 합니다.
6. **문서 간·합계 지적의 처리**: 값 입력칸이 없습니다. 수정 승인하면 다시 계산한 값으로 바뀝니다. P0 시연에서는 나오지 않고, 테스트에서만 나옵니다.
   - **보완**: 이 두 지적에는 "현행 유지"를 막고 "수정 승인"만 허용합니다. 계산값이 문서마다 다른 채로 남으면 안 되기 때문입니다. 화면에는 수정 승인 버튼만 보입니다. 처리 함수도 현행 유지를 거부합니다. 테스트 5번으로 확인합니다. 그래서 완료 기준은 "검사 테스트 5/5 통과"로 바뀝니다.
