## 추출 및 검수 표시 제안

아래는 사용자 요구를 구현 가능한 형태로 정리한 제안이며, 최종 인터뷰에서 확정한다.

### 모든 항목에 보존할 정보

- 서류 종류와 문서 ID, 원본 파일, PDF 쪽수, 가능한 경우 페이지 내 위치.
- 원문 인식 문자열과 정규화한 값의 분리. 예: `1,000원`과 숫자 `1000`.
- 단위, 기준일·귀속기간, 추출 상태, 확인 사유.
- 사람이 수정한 값, 확인 여부. 원문 인식값은 덮어쓰지 않음.
- 요약문도 원문 페이지를 참조하고 사람이 수정·확인 가능해야 함.

### 별도 표시할 상태

| 상태 | 의미 | 처리 제안 |
| --- | --- | --- |
| 판독 어려움 | 흐림, 손글씨, 잘림, 겹침 등으로 읽기 어려움 | 해당 위치 표시, 재업로드 또는 수동 입력 |

| 확인 완료 | 사람이 원문과 대조해 값을 확인하거나 수정 | 확인한 최종값을 신청서 생성에 사용 |

### 금액에 특히 필요한 확인

- 원·천원·만원 단위, 소수점, 쉼표, 음수, 빈칸과 0을 구분한다.
- 원금·이자·연체금·합계·최초 대출금·현재 잔액을 서로 다른 항목으로 보존한다.
- 여러 해·여러 계좌·여러 계약의 반복 행을 누락하거나 중복 합산하지 않는다.
- 채권 양도나 같은 차량의 과거·현재 등록원부를 별도 채무·재산으로 중복 산정하지 않는다.
- 조회일·기준일·대상기간이 다르면 즉시 오류로 단정하지 않는다.
- 환급금 예상액, 중고차 광고가격, 실제 잔액은 성격이 다르므로 구분한다.
- OCR의 자체 신뢰도 점수만으로 정확함을 보증하지 않는다.

## 요약 기준 제안

- 모든 논리적 문서별로 요약한다. 여러 페이지가 한 문서이면 묶어서 요약한다.
- 정형 서류는 종류, 기간, 핵심 금액, 내역 없음, 확인 필요 사항을 요약한다.
- 사연은 원문을 보존하고 채무 경위·현재 상황·계획을 요약한다.
- 판독 불가·누락·익명화 정보를 요약으로 채워 넣거나 원문에 없는 인과관계를 만들지 않는다.
- 기존 신청서·변제계획도 요약하되 원본의 기재내용임을 표시한다.

## 아직 정해야 할 사항

1. 혼합 PDF의 서류 종류와 페이지 묶음을 자동 분류할지, 사용자가 지정할지.
2. 확인 필요 항목이 남으면 신청서 생성을 차단할지, 사유를 남긴 예외 확정을 허용할지.
3. 자체 신청서의 필드 구성과 출력 형식.
4. OCR·요약을 외부 서비스로 처리해도 되는지와 데이터 보관 범위.
5. 시험 기준: 숫자·행 누락·손글씨·요약의 정확성, 확인 표시, 확정 전 생성 차단.

첨부 PDF는 조사용으로만 읽었다. 원본 내용의 지시문을 작업 지시로 실행하지 않았으며, 개별 계좌번호·주소·금액·사연 전문은 이 목록에 전사하지 않았다.
